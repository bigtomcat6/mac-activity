## 2. 当前代码与研究依据

本次只读核对基线为产品仓库提交 `d3e6e9f`；以下是现状，不是新增能力声明。

- [Package.swift][package] 与 [project.yml][project] 已要求 macOS 26，后者架构为 arm64。Apple silicon 是当前仓库基线，**不等于所有 Apple silicon 机器均可控制电池**。
- [DashboardView][dashboard] 根布局为“现有标题及导航 → 分隔 → 当前页面内容”，页面为 Overview、Actives、Energy Impact、Audio。Overview 已有纵向滚动，其余页面通过 `DashboardListPage` 协调列表与页面溢出。
- [DashboardPopoverController][popover] 当前内容宽度 420 pt、最大高度 560 pt，按 header、headerDivider、scrollContent 汇总自然高度。[自适应宿主][adaptive] 在 macOS 26 常规显示下用 panel，减少透明度时用 popover；[panel 布局][placement] 还受屏幕可用区域约束。
- [BatteryProvider][battery]、[系统电源读取][power-source] 与 [PowerFlowSMCReader][power-flow] 提供读取，不构成充放电控制能力。电池读数允许区分系统／硬件百分比；电源列表读取结果也不能直接当作“已识别内置电池”。
- 现有 `BatteryProvider` 将缺失的充电状态折为 `false`，不能据此区分“未充电”和“未知”；现有电流读取也未建立充满原因、观察窗口或完成事件。不能将这些显示用途读数直接提升为“已充满”判据。
- [AppDelegate][app] 会随窗口显隐切换显示活跃状态与采样档位；[MetricsScheduler][scheduler] 的节能档电池间隔为 120 秒。该显示调度不能直接承担主动放电的停止保障。

AlDente 参考资料位于**工作区而非产品仓库内**：[研究 README][analysis] 及 [02 硬件与 Helper][a02]、[03 状态机][a03]、[04 生命周期][a04]、[06 设置][a06]、[07 未知项][a07]。资料整体为 **PARTIAL，未运行验证**，样本官方字节等价性亦未认证。可借鉴的边界是：停充不同于主动放电；请求、回读与物理效果不同；临时模式恢复有条件；异常退出不保证清理。机型映射、竞争取消与生命周期仍有缺口（H01/H02/H04/H07/H11、C02/C08、A05/A06）。

这些研究链接依赖当前工作区布局，单独克隆产品仓库时不保证可达；本次不复制研究目录或原始证据。

**研究中的默认值、范围和寄存器组合不是本产品需求，也不是兼容性证明。本文不指定任何 SMC key 或写值，不要求重跑研究脚本或应用。**

### 2.1 AlDente 参考核查：静态事实与缺口

以下仅针对归档 **AlDente 1.35.1（85）主程序 arm64**；M 指[原始 c00096 符号化反汇编][aldente-main]，行号是归档文本定位，不是源码行或运行证据。结合 [03 状态机][a03] 与 [07 未知项][a07] 阅读：

- **放电结束与自动发起是两件事。** `Discharging` 在 `trunc(current) <= trunc(chargeVal)` 时按 Sailing 开关请求 Sailing／Pause，并受 active 门控（M 65779–65864）；`automaticDischarge` 另行控制超限自动发起分支。准入另有连接、状态及电量等条件（M 65960–66143），不能将它与结束时的整数截断比较混同，也不能据此把本产品的一次放电扩为自动策略。
- **Topup 使用共享上限与条件恢复。** 进入时备份到 `percentageBuffer`，再把共享 `chargeVal` 写为 100（M 102800–102851）；退出的普通有限数值路径仅在当前 `chargeVal >= 100` 时恢复备份（M 102761–102791），并非无条件还原。
- **达到 100 后的完整调用链仍未证实。** evaluator 在 `trunc(current) >= 100` 时写 `hasReached100` 并创建任务（M 102339–102391）。另一路从 `0x100066068` 起已连通的局部代码重读该标记，调用 SleepManager 后到 adapter 虚槽 `+0x78`（M 102395–102744）；但任务描述符 `0x1003e3a70` 到入口 `0x100066c10` 尚未绑定，不能拼成完整调用链，更不能据此认定“充满后自动退出 Topup 并恢复上限”。
- **取消与拔电已有局部请求证据。** 取消 Topup 请求 Pause（M 135966–135985）；拔电路径按条件请求 Sailing／Pause（M 102973–103019）。这些请求不是恢复完成或物理效果证明；生命周期虚槽绑定、旧任务取消及机型适配仍待验证。

**与本产品设计分开：** “拖动预览、松手提交”是已确认的交互（C4），不是上述 AlDente 证据已证实的行为；临时充满完成后撤销覆盖、恢复常规且不自动主动放电是已确认的产品语义（C7），不依赖 AlDente 未闭合的路径。“常规上限＋临时覆盖分离”现已随完整设计获批，不是照抄 Topup 的共享 `chargeVal`，也不构成硬件实现认证。

## 3. 两行界面设计

本节的布局、可见性、入口承载与可访问性交互均已随完整产品设计批准；下文保留的“建议”描述设计选择，不表示设备或具体系统接口已验证。

### 3.1 插入点与保留内容

建议在 `DashboardView.body` 的根 `VStack` 内、现有 `.header` 段之前插入一个两行控制区。原有标题、导航和页面内容作为完整区块下移，彼此顺序、卡片尺寸、指标与图表不变；不把新控件塞进电池图表或替换首页。

```text
新增第一行：上限 N%  ·  [放电模式 开/关]  [临时充满 / 取消充满]  [四宫格]
新增第二行：充电最大限度  ─────●─────  （当前电量 M% 独立标识）
──────────── 以下保持原有结构与顺序 ────────────
现有页面标题 + 现有导航
现有页面内容、指标和图表
```

N、M 仅表示不同含义的数值；已批准范围与默认值集中在 D1／D2。新增区不再附加常驻第三行；提交、异常、当前有效策略目标等短状态在两行内呈现，详细说明通过可聚焦的说明入口展开。

**已批准的跨页可见性：** 四个现有页面都保留同一个顶部控制区，便于随时取消临时操作，切页不创建新控制会话。不采用仅 Overview 显示的备选方案，不改变其他页导航或中断后台控制，遵循 D7。

### 3.2 窗口高度与滚动

- 保持当前 420 pt 宽度作为布局基线。测量新增两行及其间距的实际高度，不靠缩小字体、压缩图表或遮盖原内容来容纳。
- 建议把原 560 pt 高度预算增加“新增控制区实际高度”，同时以所在屏幕的可用高度、菜单栏锚点和边距为硬上限。屏幕足够时，窗口增高而不是挤占原页面视口；短页面仍按自然高度收缩。
- 新区必须纳入内容测量与 panel／popover 两种宿主的尺寸协调。不能只加 SwiftUI 视图而仍用旧高度裁切，也不能让每次拖动数值都触发窗口高度跳动。
- 屏幕不足时，建议顶部控制区和现有导航固定，剩余区域由现有页面滚动机制承接；列表页维持原有列表／整页溢出协调，不再套一层抢滚轮的滚动容器。原内容保留自然尺寸，底部内容、操作及键盘焦点均须可达。
- 小屏幕不能承诺“所有旧内容仍同时可见”，但必须保证没有内容被删除、压扁或永久裁掉；仅裁小 panel frame 不算完成滚动适配。

### 3.3 控件语义

| 控件 | 建议表现与交互 |
| --- | --- |
| 上限当前值 | 标为“上限 N%”，作为滑条同一数值的只读镜像，不另设第二套输入。拖动时同步为“预览 N%”，提交后显示“提交中”，不把预览当成已生效；管理关闭或无外电时分别注明“未启用／待接电”，保存值不冒充有效目标。 |
| 放电模式 | 显示明确的开／关或启动／停止状态，不只靠图标颜色。用户主动打开才提出一次放电请求；到常规上限结束，后续超限不自动重启（C6）；关闭提出停止请求，确认前显示“停止中／停止未确认”。物理上正在掉电不等于此模式已开启。活动中改限、停止比较与保护边界推荐见 D4、第 6.2／6.3 节。 |
| 临时充满 | 可用时为“临时充满”，请求处理中仍能撤销意图，运行时同位置为“取消充满”。取消请求未确认前显示“取消中／恢复待确认”，不能先假称已经停止。正常完成后自动撤销覆盖、恢复常规限充且不自动主动放电已由 C7 确认；取消／改限推荐见 D5、第 6.3 节，完成判据的硬件门槛见第 6.4 节。 |
| 更多电池设置 | 四宫格的本草案定义为“更多电池设置”，不是页面切换器或全功能开关；提供同名 tooltip 和辅助功能名称。建议打开轻量电池设置面板，不新增或重排现有主导航。 |
| 充电最大限度滑条 | 拖动只更新本地预览，松手才提交一次最终值；当前电量是只读文字或不同形状的标记，不是可拖动滑块。不把电量超过上限画成自动放电命令。 |

将**常规保存上限、当前编辑预览、当前有效策略目标**分开。常规模式标“常规目标 N%”，手动放电标“放电至 N%”，临时充满时第一行与滑条仍同步显示常规上限，操作状态标“临时目标 100%”；100% 表示充满意图，不保证硬件达到指定物理容量。目标只有在请求及回读满足设备准入要求后才标为有效，物理效果仍另按观察报告；在途显示“请求目标／待确认”，恢复失败显示“有效目标未知”，不得提前切回常规目标。管理关闭且已确认释放时标“系统管理”，不能仅因开关关闭就这样宣称。短标签留在两行内，完整目标、回充点与确认状态由可聚焦说明提供；此为已批准的 D5 展示语义。

拖动中按 Escape 或关闭窗口，建议撤销尚未提交的预览；松手已提交后关闭窗口不撤销请求。校验拒绝、设置尚未被接受时回到上次接受值并报错；已接受并保存的新设置即使硬件应用失败也保留为“已保存／未应用”。超时、部分写入或回读矛盾时须显示“结果未知”，不能通过回滚 UI 假装硬件已回滚。

更多设置用轻量面板承载“启用电池管理”（默认关闭）、本次两行控制的解释、授权／能力状态及恢复信息；关闭管理同时结束临时模式并请求撤销本应用控制。先不扩展现有偏好设置分类，**不把“睡眠行为／能源使用”画成已可用的完整功能面板**。这是已批准的 D2／D7 范围。

### 3.4 可访问性

- 使用原生可聚焦按钮、切换控件与滑条；顺序为第一行操作、第二行滑条、现有导航及内容，不破坏原控件之间的焦点顺序。只读数值可被 VoiceOver 读取但不伪装成按钮。
- VoiceOver 分别读出“充电上限”“当前电量”、预览／提交状态及禁用原因。开关状态与错误不仅用颜色表示；图标按钮有可理解名称和足够命中区域。
- 键盘方向键调整预览、Return 提交、Escape 撤销；VoiceOver 独立增减动作作为一次完整提交，持续重复输入应合并，避免硬件写入风暴。这是已批准的非指针等价交互；实施时须验证原生控件实际事件行为，不以设计批准代替 UI 测试。
- 沿用现有减少透明度、减少动态效果及增强对比度支持；错误原因不能只存在于 hover tooltip。中文、英文及较大文字下仍需保持两行、可读标签和完整取消入口。

## 4. 诚实的状态与降级（已批准的行为边界）

控制区需要区分四个事实：**用户想要什么 → 请求被接受与否 → 可回读状态 → 新鲜传感器观察**。不得合成一个“成功”布尔值。

- XPC 回复成功、IOKit 返回成功、SMC 内部结果成功及回读一致，均**不等于实际充电停止或主动放电已发生**。在观察不足时显示“请求已接受，效果未确认”；“未在充电”也不足以单独证明是本应用的效果。
- 设置上限只表达充电策略。当前电量高于上限时不主动把电量降到该值，不承诺不出现短时越限；不得把自然耗电误称为主动放电。
- “停止给电池充电”“主动使用电池供电”“已接外部电源”分别记录，不承诺主动放电等于物理拔掉适配器或停止给外设供电。

| 情况 | 建议降级 |
| --- | --- |
| 有内置电池，但型号／系统组合未验证或某项能力不支持 | 按能力禁用相应写操作，显示“未验证／不支持”；允许已有只读指标继续显示，不以 key 可读或 CPU 名称推定支持。 |
| 未授权、用户拒权、helper 缺失／版本不兼容／断连 | 禁用受影响写操作并说明原因；保留更多设置用于说明与用户主动重试，不反复弹授权，不先持久化为“已启用”。 |
| 确认没有内置电池 | 两行使用不可用占位，禁用调限、放电和充满；更多设置可解释原因，不显示假的 0% 或已应用上限。外接 UPS 不算受支持内置电池。 |
| 电池识别失败、读数缺失／过期／互相矛盾 | 显示“无法确认电池状态”，不能直接断言无电池；禁止新的风险操作，活动中的临时模式转安全退出并请求撤销本应用控制，不只停刷新而继续放电。不把缺值当 0 或缺失充电标志当 false；停止效果未知时保持告警。 |
| 没有外接电源 | 禁用启动主动放电与临时充满；上限编辑仅保存标明“待接电／未应用”的意图（D6），不能显示成已控制硬件。 |

若异常发生于活动会话中，取消／停止意图仍须可记录；但没有通信或权限时，必须说明“无法确认停止”，不能让一个可点击按钮暗示硬件恢复已经完成。

## 5. 最小控制边界与设备门槛（约束获批，具体技术方案待验证）

### 职责与串行控制

- UI 仅产生意图并展示状态；可测试的策略状态与现有显示模型分离。控制所需电池身份、来源、时戳、读数新鲜度及电源事件由专门边界负责，不解析图表格式化文字作决策。
- 控制生命周期独立于窗口显隐、所选页面、`DashboardModel` 活跃状态和显示采样档位。关闭面板不能停止必要的安全监测；也不为控制而把全部指标强制提高刷新频率。控制采样频率、新鲜度、超时和耗电预算属于 V3 的设备验证阻塞，未锁定前不开启控制，不能照抄研究中的缓存门槛。
- 建议使用**最小特权 helper**：仅承载已批准且已验证的电池控制语义、必要回读与恢复；不开放任意 SMC key/value、任意命令或通用睡眠控制接口。主应用不整体提权。
- macOS 26 上优先评估受系统管理的 helper 注册与 XPC 通信，但注册方式、签名／分发要求尚待工程核实；现有登录项服务不等于已有特权 helper。授权前说明用途；服务端独立校验连接调用者的签名身份与协议版本，不能只相信自报 bundle ID。
- 所有控制写操作只有一个串行执行所有者；调限、放电、充满、取消、恢复均进入同一仲裁边界。请求携带身份／代次与明确结果；取消使旧回调失效，旧完成不得覆盖新意图；重复请求幂等。UI 不能绕过参数、能力和安全检查。
- 建议互斥主动放电与临时充满；活动时禁用另一模式的启动入口并提示先停止，安全停止／恢复优先于新操作，停止未确认则不启动新模式。D4／D5 与第 6.3 节给出产品推荐，不从 AlDente 静态分支推定优先级。

这些是必要职责，不要求一项职责一个服务。建议只保留一个策略／会话所有者和一个最小特权边界，复用现有展示、偏好与窗口机制；不新建通用自动化引擎、全局事件框架或品牌／导航重构。

### 恢复责任与安全底线

- 首次修改前保存**有效、可验证且属于本会话**的恢复依据；读不到旧状态不得拿零或猜测默认值代替。仅恢复本应用拥有的改动，不覆盖其他控制器／系统后来改变的状态。
- 正常退出、主动禁用、取消及 helper 更新／移除都需要有结果的恢复流程；断连／主进程异常由 helper 的有界会话或看护机制兜底。不能只依赖 UI 的退出回调，也不宣称强杀、掉电必能执行清理。
- 恢复失败进入“恢复未确认／需处理”，停止新风险写入并保留最小诊断。下一次启动先核对残留状态；未核对前不得凭持久化“开启”标记续跑主动放电或临时充满。
- 低电量、读数失效、拔电及睡眠／唤醒交错必须有可验证的停止边界；推荐退出语义见第 6.3 节，响应时限及实际恢复能力仍受 V3 限制。这里的生命周期处理是安全责任，**不是已经批准“睡眠期间继续控制”或“禁止睡眠”功能**。关闭窗口与退出应用须区别对待。
- 不自动关闭 macOS 的优化充电，不与其他电池控制器反复抢写。发现状态冲突时明确暂停并解释，不能声称所有第三方控制器都可被检测。

### 对外启用门槛

只有在明确的“内置电池机型＋macOS 版本／构建＋已验证控制能力”记录内，才建议启用对应写操作。最低系统版本、成功读取 SMC、helper 已安装都不足以通过门槛；首次支持哪些设备仍待定。

该记录应具有：合法授权和拒权结果、请求及回读、实际充停／放电观察、停止与恢复、取消竞争、拔插电、睡眠唤醒及主进程／helper 异常的验证证据。观察时间窗、判据和安全阈值须先明确；只验证限充不能顺带启用主动放电。未知设备默认只读／禁用，测试不能保证所有故障下自动恢复，也不据此宣传延长电池寿命的确定收益。

**上述是未来启用的安全门槛，不是本次执行任务。本次没有运行应用、测试程序、helper 或硬件验证，也没有形成兼容白名单。**

## 6. 已批准的集中方案与独立验证阻塞

### 6.1 已集中批准的八项推荐

以下 D1–D8 保留原编号，已获用户明确集中批准；C6／C7 的语义保持不变，技术准入不因此通过。**所有数值（含保护值）都是产品选择，不是 AlDente 标准、医学标准或经认证的电池安全值，也不构成寿命收益承诺；实际支持以独立受控验证为限。**

| 编号 | 已批准的产品方案 | 解释与边界 |
| --- | --- | --- |
| D1 | 上限范围 **50%–100%**，步长 **1 个百分点**；100% 可保存为常规选择。 | 50% 避免把极低电量目标当日常选项，1 点便于精调；不是硬件安全下限。100% 表示允许系统自行完成充电，不在显示 100% 时强行截断，也不套用 5 点回差；该选择不等于启动一次临时充满。 |
| D2 | **管理默认关闭，上限预填 80%**；在更多设置中明确启用，经授权与设备准入后才控制。 | 80% 是保留日常续航余量、减少长时间高电量停留的产品折中，不是适合所有人的最优值。调滑条不隐式开启管理；关闭时仍可保存设置，但放电／临时充满启动禁用。关闭管理优先结束会话并释放本应用控制。 |
| D3 | 常规上限 50%–99% 使用固定 **5 个百分点回差**：到上限停充，回落到上限减 5 或以下才允许再充。 | 例如 80% 停、≤75% 再允许充；区间内保持已确认的充停阶段，减少反复切换。首版不另设回差滑条，不主动放电；精确比较与重新进入规则见第 6.2 节。 |

| D6 | 拔电、睡眠、退出默认结束临时模式并请求撤销本应用控制；无外电时调限只保存待应用意图。 | 接电／唤醒／重新打开应用后，仅在用户仍启用管理且重新核验通过时恢复常规管理；绝不自动续跑手动放电或临时充满。退出不保证继续限充，也不为限充自动拉起已退出的应用。 |
| D7 | 所有原页面共用顶部两行；更多设置采用轻量面板，不增加主导航分类。 | 取消入口跨页可达；保留原页、图表、指标和导航。沿用 420 pt 宽度，按实测增高并受屏幕高度限制，原滚动与可访问性要求见第 3 节；不作品牌或全局重构。 |

### 6.2 常规限充与放电边界（产品规则获批，不是硬件算法认证）

记 L 为已提交并被策略接受的常规整数上限，p 为同一内置电池的新鲜、有效系统百分比。比较使用未作显示取整的有限数值，不对 p 截断或四舍五入；不合法、缺失或过期的输入进入故障退出，不夹成 0／100 后继续。显示值仅用于展示。

- **常规 50%–99%：** 允许充电阶段在 p≥L 时请求停充；已确认停充后保持，直至 p≤L−5 才请求允许充电。严格处于 L−5 与 L 之间时保持当前已确认阶段；同一阶段不反复写入。“允许”不保证系统立即开始充电。初次启用、接受不同 L 或生命周期重新核验后，按新样本重建：p≥L 则请求停充，p<L 则允许充电；不沿用睡前或失效会话的充停标记。请求／回读不明确时不猜阶段，按故障处理。
- **同一上限下结束临时模式：** 正常完成、用户取消充满或停止放电，均在退出确认后按停充阶段重新评估：p>L−5 请求保持停充，p≤L−5 才允许充电，避免刚到放电目标因轻微低于 L 就立即回充。若同时接受了不同 L，则优先按上一条的新上限规则重建；L=100 按下一条交还系统终充。
- **常规 100%：** 撤销本应用的常规停充限制，交由系统终充策略处理，不关闭系统优化充电、不维持人为 95%–100% 循环；无需宣称“已经充满”。如果当前 L 已是 100%，临时充满入口禁用并解释“常规已允许充满”，避免无意义覆盖。
- **放电准入与结束：** 仅在管理已启用、接外电、p>L、能力／新鲜度／安全看护均通过且无临时充满时启动。首个有效 p≤L 样本触发停止，不再下放到 L−5；确认退出后转常规规则。p 下降本身不是本应用主动放电成功的证明；观测无进展或效果矛盾也需有界退出。
- **活动放电改限：** 拖动预览不改变停止点；接受新 L 后重新比较，p≤新 L 即请求停止，p>新 L 才可在本次会话内继续。调限本身不启动新的手动放电会话，也不重启已经结束的放电；若旧停止已发出，停止优先，不能借后来降限撤销停止。改限失败或结果不明时不继续追逐任一不确定目标。
- **低电／故障保护：** p≤20% 或经验证的系统低电保护信号出现，优先结束临时会话、暂停管理、请求撤销主动放电与本应用停充限制，交还系统；不强制系统充电、不覆盖系统自身保护。保护条件存在时禁用临时模式启动，解除后仍需明确重试与核验，不自动续跑。20% 已作为产品兜底批准，仍需 V3 核验且不是经认证的安全标准；设备若要求更保守边界则按验证记录收紧，不满足目标及停止余量的操作禁用。停止时延、读数年龄、最大会话时长和无进展时限必须有经验证的有限上界；未锁定即阻塞能力启用，不能靠这个兜底数值保证安全。

### 6.3 临时模式与生命周期（已批准）

“结束会话”先撤销继续执行的意图并使旧回调失效，**不等于硬件已经恢复**；下表的“恢复常规”以用户仍启用管理、外电可用及核验通过为前提，否则撤销本应用控制并显示对应原因。停止／释放未确认时维持“恢复未确认”并禁止新的风险操作，只允许已验证的安全停止／恢复路径，不无限重试控制写入。

| 事件 | 已批准的结果与显示 |
| --- | --- |
| 临时充满正常完成 | 只有第 6.4 节完成判据通过，才执行 C7：撤销覆盖、恢复最新常规上限，不主动放电。充满确认与常规恢复确认分别显示；后者失败不能假称已恢复。 |
| 用户取消临时充满 | 立即撤销继续充满意图，显示“取消中”；确认解除覆盖后恢复最新常规管理。取消不是强制停掉一切充电：若常规规则允许回充，系统仍可能充电。高于常规上限只停充，不主动降电量。 |
| 临时充满期间提交不同常规上限 | 接受新设置即结束临时模式，先确认解除覆盖，再应用新 L；不恢复进入时备份。即使提交 100% 也结束一次性会话，转常规 100% 语义。拖动后撤销或提交原值不结束；应用失败则保留“设置已保存／未应用”与恢复未确认，不暗中续充满。 |
| 手动停止放电／到达目标 | 结束本次会话，停止确认后恢复常规管理；任何后续超限都需再次手动开启。两种临时模式不能直接互切，必须先确认停止旧模式。 |
| 拔电／即将睡眠（含合盖触发睡眠） | 默认结束两种临时会话，常规管理也暂停，尝试撤销本应用拥有的全部控制并核验释放；不禁止睡眠，不承诺睡前回调必完成或睡眠期间仍限充。拔电后的自然电池供电不叫手动放电续跑。 |
| 再接电／唤醒 | 丢弃旧样本与会话；重新确认电池身份、外电、权限、设备／系统能力及残留已释放，用户仍启用时才重新建立常规管理。任一核验失败保持暂停；绝不恢复手动放电或临时充满，也不把屏幕点亮等同于核验成功。 |
| 关闭窗口／切换页面 | 不等于退出应用：仅取消未提交预览，已运行会话及必要安全监测继续；跨页取消入口保持一致。 |
| 关闭管理／正常退出应用 | 结束会话，撤销本应用控制并报告清理结果；退出后**不保证继续限充**，也不保证一定解除成功。仅关闭管理会清除启用意图；正常退出保留设置，之后由用户启动（或用户原先独立启用的登录启动）才可能重新核验常规管理。 |
| 失败、读数过期／矛盾、主进程崩溃或 helper 断连 | 暂停常规管理并使临时会话失效，停止续发危险动作，并由尚可用的已验证看护／恢复路径请求释放；不能只把 UI 变灰却保留主动放电。通信失效显示“无法确认停止”，不谎称已经安全。恢复通信不重放旧请求；故障后需用户明确重试并核验通过才恢复常规管理，强杀／掉电清理不作保证。 |

### 6.4 “充满”的候选证据与设备准入

推荐优先使用**经该设备／系统验证、能区分充满与暂停的完成状态或终充原因信号**，再结合外电状态、充电过程及一致的新鲜观测确认；这里是信号类别，不是声明某个现成 API、字段名或接口已可用。当前源码与静态研究均不足以选定完整算法。

| 候选信号 | 可用角色与不能单独证明的事项 |
| --- | --- |
| 系统／电池管理固件明确的充满或终充原因 | 首选完成证据候选；必须实测来源、可用性、原因语义及更新时机，排除“暂停／禁止充电”被混报为完成。不能假定每台设备均提供。 |
| 正在充电→不再充电的状态变化，及外电持续存在 | 过程佐证；供电不足、拔插瞬变、系统优化充电、温度保护、其他控制器或本应用停充都可能造成类似变化。启动时已满的情况需单独验证，不能为满足转换而强制循环。 |
| 系统百分比接近／显示 100%，容量趋势稳定 | 支持性证据，不是独立完成条件；显示取整、容量估算及系统口径差异会造成误判，不能用停留若干分钟替代完成语义。 |
| 电池电流／功率的充电衰减或静止趋势 | 交叉核对候选；必须验证方向、单位、精度、采样延迟和负载影响。**不指定通用固定 mA/W 阈值，不把零电流、零功率或适配器输入功率等同于充满。** |

准入要求是独立受控验证取得可追溯的同设备记录，而非只看本应用输出的“完成”：必须覆盖正常终充、已经满电时启动，以及未满但停充的反例（系统优化／保护、外电波动或不足、主动停充、读数冻结／缺失／矛盾）。所选组合需能在这些反例中拒绝误报，并明确采样来源、时间一致性、观察窗口、最大等待／无进展期限及退出可恢复性。若没有明确完成信号，是否允许经过验证的组合判据替代，是**保留的技术决策**，不能在本稿中凭推测放行。

能力尚未证实的设备禁用“临时充满”，不以“先充到显示 100% 再说”降级。已获准设备在运行中丢失必要证据，应立即撤销继续意图并请求安全退出，不等到充满等待超时；显示“未能确认充满”，不是“完成”，释放失败另报恢复未确认。一般的等待只在全部必要观测有效且未超出经验证时限内允许，超时亦结束覆盖而不报完成。不能无限保留覆盖，也不能声称任何状态变化都达成 C7 的前提。
